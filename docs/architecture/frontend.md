# Frontend Architecture

## Current Stack (Verified)

- Blade renders minimal SPA mount hosts; each page route returns a host view and React renders the app. The storefront SPA is mounted at `/`, `/shop`, `/categories`, `/categories/{category}`, `/products/{product}`, `/cart`, `/checkout`, and `/order-confirmation/{order}` (`store-app`); the auth SPA is mounted at `/account` (`auth-app`); the admin SPA is mounted at `/admin/*` (`admin-app`).
- `resources/js/app.js` mounts each React experience when its element id (`#store-app`, `#auth-app`, `#admin-app`) is present. It imports `tokens.css` (CSS variables design tokens) and `ui.css` (neutral shared primitive classes) before application stylesheets (`store.css`, `admin.css`, `auth.css`). React calls same-origin `/api` endpoints through Axios.
- Shared React primitives reside in `resources/js/components/ui/` (`Button`, `Card`, `Field`, `Input`, `Select`, `Textarea`, `Alert`, `Badge`, `PageHeader`, `Money`, `Table`, `EmptyState`, `Skeleton`, `Steps`) and provide consistent accessibility, styling, and tabular data displays without external component libraries.
- Bootstrap 5 is imported through Sass. Tailwind CSS 4 is imported from `resources/css/app.css` and processed through the Tailwind Vite plugin.
- React 18 is installed with the Vite React plugin. Axios sends Sanctum session cookies and XSRF headers.
- The public storefront is a React SPA using React Router (`resources/js/components/store/StoreApp.jsx`) with Redux Toolkit for cart state (`resources/js/store/{store.js,cartSlice.js}`). Cart lines (`{product_id, vendor_id, quantity}`) persist in `localStorage` under `goodgoods.cart.v1`; every change dispatches an abortable, debounced `fetchQuote` thunk that posts to `POST /api/cart/quote`. No price is ever computed in the browser.
- Store pages (`components/store/pages/*`) fetch the public catalog with `window.axios` and local loading/empty/error state. `CheckoutPage` provides two-column responsive layout, field errors, guest prompts, and handles 409 re-quotes. `OrderConfirmationPage` displays order and vendor sub-orders with rule labels and cleans up cart state.
- `/admin/*` routes mount a React admin workspace from a minimal Blade host. React selects dashboard, vendor, category, product, discount-rule, customer, and order screens from the browser path and uses same-origin Axios requests to protected `/api/admin/*` endpoints.
- The admin Orders index provides multi-faceted filtering (vendor, customer, status, date range, search) with URL persistence and items count. The order detail screen provides sub-order status controls and vendor notification dispatch.
- Admin forms provide client-side workflow states while Laravel Form Requests remain the validation authority. API validation errors and session-stored success feedback are rendered in React.
- `vite.config.js` builds the CSS, Sass, and JS entry points. There is no Inertia or Livewire integration in the inspected application.
