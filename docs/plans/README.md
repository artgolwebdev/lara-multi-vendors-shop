# Implementation Plans

`backlog.md` is the central index. Give each substantial, approved task one stable sequential ID and one plan file. Use only `proposed`, `ready`, `in_progress`, `blocked`, `completed`, or `cancelled` as plan/backlog statuses. Small, low-risk fixes can use a proportionate workflow without creating a plan.

1. Select the next ID and add a backlog entry; do not reuse IDs.
2. Copy [PLAN-TEMPLATE.md](PLAN-TEMPLATE.md) and fill in evidence, scope, ordered tasks, and acceptance criteria before substantial implementation.
3. Update the plan as work progresses, including blockers, discoveries, and actual validation results.
4. On completion, record the summary and remaining work, update the backlog, and retain the plan as history.

Only identified project needs belong in the backlog. Do not create plans for hypothetical marketplace features before requirements are confirmed. See [the initial project foundation plan](001-project-foundation.md).
